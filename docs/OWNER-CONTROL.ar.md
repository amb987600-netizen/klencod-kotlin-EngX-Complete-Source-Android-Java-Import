# لوحة تحكم المالك (Control)

هذه لوحة منفصلة عن حسابات التطبيق العادية، ولها بيانات اعتماد مستقلة. قبل استخدام التطبيق، يبلغ المالك كل مستخدم شخصياً بأن المالك يطّلع على البيانات التي تتم مزامنتها. الوصول هنا **ليس باباً خلفياً**: لا توجد كلمة مرور ثابتة أو master password، ولا يتحول مالك مساحة عمل عادية تلقائياً إلى حساب لوحة التحكم.

## النطاق

- `primary` يرى السجلات التشغيلية المتزامنة غير المحذوفة في مساحات العمل غير الملغاة، وحسابات المستخدمين وعضوياتهم وسجل التدقيق، ويدير حسابات المساعدين. لا يفك تشفير النسخ الاحتياطية أو يقرأ البيانات غير المتزامنة ومحادثة المساعد المحلية.
- حسابات `assistant` اختيارية في الخانات 1–3. يحدد المالك لكل حساب مساحات العمل والمجالات وأنواع السجلات المسموح بها، إضافة إلى صلاحيات رؤية المستخدمين وسجل التدقيق وتعليق العضويات. القوائم الفارغة تمنح الصفر من الوصول، ولا توجد wildcard مثل `*`.
- تُقرأ المنح من قاعدة البيانات في كل طلب؛ تغييرها أو تعطيل الحساب يسري فوراً. تغيير كلمة المرور أو إعادة التعيين يبطل الجلسات القديمة فوراً.
- لا يمكن للمساعد تغيير الخانات أو الحساب الأساسي، ولا تعديل عضوية مالك المساحة أو الحساب الأساسي. لا يوجد حذف تدميري للبيانات.
- سجل التدقيق يسجل القراءات الحساسة والتغييرات ومحاولات الرفض، ولا يخزن كلمات المرور أو رموز الإعداد.

## الإعداد والتشغيل

من نفس بيئة تشغيل الخادم ومجلده، وبنفس `DATABASE_PATH` و`JWT_SECRET` الفعليين، أنشئ رمزاً لمرة واحدة صالحاً 30 دقيقة. لا تنفذ الأمر على قاعدة بيانات أخرى أو قبل ضبط `.env`:

```bash
cd server
node control-cli.mjs setup-code
```

يُستخدم الرمز مرة واحدة في `POST /api/control/setup` مع `email`, `password` (12 حرفاً على الأقل)، و`name`. لإعادة تعيين الأساسي:

```bash
# من داخل مجلد server وبنفس إعدادات الخادم
node control-cli.mjs reset-primary
```

لا يعمل reset قبل أول claim، ويتطلب البريد الأساسي. الرمز لا يظهر في قاعدة البيانات بصورته الأصلية.

## نقاط API

- `GET /api/control/status` — `{configured}`.
- `POST /api/control/login` — دخول بيانات اعتماد اللوحة.
- `GET /api/control/me` — الحساب والدور والمنح الفعالة.
- `POST /api/control/password` — تغيير كلمة المرور وإصدار جلسة جديدة.
- `GET/PUT /api/control/assistants` و`/assistants/:slot` — إدارة الخانات 1/2/3 للـ primary.
- `GET /api/control/overview`, `/records`, `/audit` و`PATCH /memberships` — القراءة والإدارة وفق الدور والمنح الدقيقة.

رمز لوحة التحكم منفصل تشفيرياً عن JWT الخاص بالتطبيق؛ لا يقبل API العادي رمز اللوحة، والعكس. الخدمة مصممة لبيانات السحابة المتزامنة فقط؛ لا تدّعي قراءة بيانات محلية أو غير متزامنة.

## الدخول من التطبيق

افتح زر الدرع أعلى التطبيق أو «لوحة المالك والمساعدين» في الإعدادات أو شاشة اختيار القسم. أدخل عنوان خادم EngX المجهّز عبر HTTPS، ثم اختر «إعداد أولي» واستخدم الرمز واسمك وبريدك وكلمة مرور جديدة. بعدها يكفي تسجيل الدخول بهذه البيانات. لا توجد حسابات جاهزة أو كلمات مرور مضمنة. من تبويب «المساعدون» أنشئ حتى ثلاثة حسابات واختر لكل منها مساحات العمل والأقسام وأنواع السجلات والعمليات. يجب تعيين كلمة مرور عند إنشاء مساعد جديد. تعديل المساعد يبطل جلساته الحالية؛ عليه الدخول مجددًا.

قوائم السجلات الفارغة في عوامل التصفية تعني «كل المسموح لهذا الحساب» وليس تجاوز المنح. كل قائمة منح فارغة عند إعداد مساعد تمنع ذلك البعد من الوصول. البيانات السحابية لا تظهر حتى يختار المستخدمون المزامنة وتصل بياناتهم فعليًا إلى هذا الخادم. واجهة اللوحة ليست وسيلة لقراءة هاتف المستخدم مباشرة.
